# ADR-001：轻量后端模板生成 + 原生 PNG 工作区

## 状态与日期

Accepted，2026-09-13。

## 背景

比赛 Demo 已有真实 RGBA 抠图、Python CV 服务与原生 Camera / Clipboard 双页。贴纸、像素、LEGO、十字绣仍是禁用占位；需要可靠展示与可用图纸，不扩张成 3D、编辑器或品牌库存系统。微信数据桥不适合一次传递三张大 base64 PNG。

## 决定

使用现有 Pillow / OpenCV / NumPy，在 `app/paste_plugins` 独立生成四种模板；复用已验证的 alpha 采样 / 色卡匹配逻辑，不改 Clipboard 核心模型。新增统一、安全校验的 `/api/templates/{kind}`，前端各插件实现同一类型接口，一个原生工作区管理参数 / 展示 / 导出 / 生命周期。

后端生成 PNG → 前端验证 kind / 字段 / 长度 → 串行写十二个固定 app-owned 文件 → `setData` 仅传路径与元数据 → 原生放大 / 用户点击保存到相册。过期请求不写展示；页面重进和预览返回有明确处理。LEGO 为同色矩形平面覆盖，清单统计实际砖块；十字绣统计真实针位，不称官方材料 ID。

## 备选与取舍

- 小程序逐格 DOM / 大 base64 `setData`：能省后端渲染，但存在真机布局走样与数据桥压力，已有失败先例，不选。
- 新建四页面 / 搬入完整开源编辑器：交互和平台适配扩大，违背双页 Demo 目标，不选。
- 新模型 / 三维积木 / 官方库存色卡：需要额外配置与校验，不在本轮范围；未来可换独立 Adapter。

## 后果与验证

无新增运行依赖；需要新版后端在线，不承诺离线生成。12 个复用文件避免无限缓存增长，但照片转换 / 保存需串行和过期保护。真实抠图若带入背景，本轮模板不会自动再分割；颜色是近似值、需实物核对。贴纸输出最长边限制 1024，拼搭是二维贪心覆盖、非最优砖数，十字绣仅给 14CT 网格估算。

测试覆盖 RGBA、图纸 / 清单一致、空孔、请求校验、本地写盘、拒绝相册权限、返回 / 换插件 / 过期请求。电脑 LAN HTTP / PNG QA 和原生编译已执行，真机视觉与相册透明度、实际材料适配由现场验收，不以合成输入代替真实照片结果。
